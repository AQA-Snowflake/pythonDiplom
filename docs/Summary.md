# Отчёт по автоматизации

## 1. Что было запланировано и что реализовано
**Запланировано:**
- Автоматизация позитивных и негативных сценариев оплаты дебетовой картой.
- Проверка UI и базы данных.
- Интеграция Allure для отчётов.
- Настройка CI/CD (GitHub Actions).
- Оформление документации.

**Реализовано:**
- Автоматизировано 17 тестовых сценариев (валидация полей, отображение цены/миль, переключение вкладок, успешная и declined-оплата) - для купить и купить в кредит параметризировано.
- Настроена генерация Allure-отчетов с историей и трендами.
- Проверка БД для сценариев оплаты для дебетовой и кредитной карт.
- Тесты успешно интегрированы в GitHub Actions.

## 2. Что не было реализовано
- Тесты на граничные значения месяца/года (01/12, текущий год).
- Проверка повторных отправок формы (идемпотентность).

**Причины:**
- Обнаружен критический баг приложения (declined-карта показывает success) — потребовалось время на диагностику и оформление.
- Общая нехватка времени после настройки окружения (Часть времени ушла на восстановление окружения (gate-simulator не в Docker, ChromeDriver на M1)).

## 3. Сработавшие риски
- **Сложность с настройкой окружения** (Docker, драйвер Chrome на M1)  — на это ушло больше времени, чем планировалось (вместо 4 часов — 10 часов).
- **Нестабильность селекторов** — пришлось несколько раз переписывать XPath из-за динамической подгрузки элементов.
- **Нестабильность локаторов уведомлений** — в DOM одновременно присутствуют `.notification_status_ok` и `.notification_status_error`, 
    оба скрыты по умолчанию. Пришлось разделить ожидания на `wait_for_success_notification` / `wait_for_error_notification`.
- **Нестандартное поведение declined-карты** — симулятор (или фронт) показывает успех вместо отказа. Потребовалось время на подтверждение бага и оформление `xfail`.
- **Проблемы с драйвером Chrome** — из-за архитектуры M1 пришлось вручную устанавливать Chromedriver.
- **Нестабильность CI/CD** — дополнительные затраты времени на настройку пайплайна GitHub Actions.

## 4. Ключевые цифр
- **Всего тестов:** 18 (17 собранных, CVC-тест параметризован ×2)
- **Успешных (PASSED):** 15 (83.3%)
- **Процент упавших (FAILED):** 0/18
- *Ожидаемо падают (XFAIL):** 3/18 3 (16.7%) — подтверждённые дефекты приложения.
- **Общий процент успеха (по данным Allure):** 100% (с учетом известных дефектов).

## 6. Результаты тестирования (основные баги)
1. **BUG-1 (XFAIL):** declined-карта `4444 4444 4444 4442` показывает «Успешно / Операция одобрена Банком» вместо ошибки — критично, блокирует корректную обработку отказов.
2. **BUG-2 (XFAIL):** валидация поля «Владелец» пропускает кириллицу.
3. **BUG-3 (XFAIL):**не подтверждён.** Ручная проверка показала, что CVC из 2 цифр
   корректно отклоняется с сообщением «Неверный формат». Изначальный `xfail`
   был следствием неверного текста в ассерте теста.
4. **BUG-4 (PASSED, #5, #6):** пустой номер карты выдаёт «Неверный формат» вместо «Обязательное поле» - замечание, не баг.

## 7. Рекомендации
- **Приоритет — BUG-1:** исправить маршрутизацию declined-карты. Проверить `data.json` gate-simulator и логику фронта — при отказе банка должен появляться элемент `.notification_status_error` с текстом об ошибке.
- **BUG-2, BUG-3:** добавить валидацию «Владелец» (только латиница, пробелы, дефисы) и CVC (ровно 3 цифры) на клиенте и сервере.
- **BUG-4:** заменить текст «Неверный формат» на «Обязательное поле» при пустом вводе.
- Расширить автоматизацию: граничные значения месяца/года, повторные отправки формы.
- Продолжить использование Allure и GitHub Actions для отслеживания истории и трендов.
