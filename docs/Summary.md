# Отчёт по автоматизации

## 1. Что было запланировано и что реализовано
**Запланировано:**
- Автоматизация позитивных и негативных сценариев оплаты дебетовой картой.
- Проверка UI и базы данных.
- Интеграция Allure для отчётов.
- Настройка CI/CD (GitHub Actions).
- Оформление документации.

## 2. Что было реализовано
- Автоматизировано 14 тестовых сценариев (валидация полей, отображение цены/миль, переключение вкладок, сценарии оплаты).
- Настроена генерация Allure-отчетов с историей и трендами.
- Тесты успешно интегрированы в GitHub Actions (Run #34760893070).

## Причины, по которым что-то не было реализовано
- Не реализованы тесты для кредитной оплаты (запланированы, но не успели).
- из-за критических багов приложения (отсутствие уведомлений), что блокирует полную проверку позитивных сценариев

## Сработавшие риски
- **Сложность с настройкой окружения** (Docker, драйвер Chrome на M1)  — на это ушло больше времени, чем планировалось (вместо 4 часов — 10 часов).
- **Нестабильность селекторов** (динамическая подгрузка элементов) — пришлось несколько раз переписывать XPath из-за динамической подгрузки элементов.
- **Проблемы с драйвером Chrome** — из-за архитектуры M1 пришлось вручную устанавливать Chromedriver.
- **Нестабильность CI/CD** — дополнительные затраты времени на настройку пайплайна GitHub Actions.

## Ключевые цифр
- **Всего тестов:** 14

- **Процент упавших (FAILED):** 2/14 (14.29%) - критические баги.

- **Общий процент успеха (по данным Allure):** 83.33% (без учета ожидаемых падений).

## 5. Результаты тестирования (основные баги)
1. BUG-1 (FAILED #1): Нет уведомлений об успехе/ошибке после оплаты.
2. BUG-2 (FAILED #12): Нет уведомлений об ошибке при отклонении оплаты.
3. BUG-3 (XFAIL #9): Валидация пропускает кириллицу в поле "Владелец".
4. BUG-4 (XFAIL #11): Валидация CVC не проверяет длину (проходят 2 цифры).
5. BUG-5: Пустой номер карты выдаёт "Неверный формат" вместо "Обязательное поле".

## 6. Рекомендации
- **Приоритетно исправить отображение уведомлений** после отправки формы – добавить компонент `.notification` с явными статусами (успех/ошибка) и текстовыми сообщениями, чтобы пользователь сразу видел результат операции (BUG-1, BUG-2).
- **Улучшить валидацию полей "Владелец" и "CVC"** на стороне клиента и сервера – настроить проверку допустимых символов (только латиница для владельца) и длины (ровно 3 цифры для CVC), чтобы исключить отправку некорректных данных (BUG-3, BUG-4).
- **Добавить информативные сообщения об ошибках** для пользователя – заменить общие формулировки на конкретные подсказки (например, "Поле обязательно для заполнения", "Введите 3 цифры CVC"), чтобы упростить исправление ошибок (BUG-5).
- Расширить автоматизацию на кредитные сценарии и оставшиеся валидации после исправления багов.
