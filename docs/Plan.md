# План автоматизации тестирования веб-сервиса "Путешествие дня"

## 1. Цели автоматизации
- Обеспечить регрессионное покрытие основных сценариев оплаты тура дебетовой картой.
- Сократить время ручного тестирования при релизах.
- Обеспечить проверку интеграции с БД и эмулятором платежей.

## 2. Перечень планируемых к автоматизации сценариев

### Позитивные сценарии
1. Успешная оплата дебетовой картой (номер `4444 4444 4444 4441`, статус `APPROVED`).  
   Ожидаемый результат: уведомление об успехе, в БД статус `APPROVED`.
2. Валидация формата номера карты (16 цифр).
3. Валидация месяца (корректное значение, например "09").
4. Валидация владельца (латиница, пробелы, дефисы).
5. Валидация CVC (ровно 3 цифры).

### Негативные сценарии
1. Оплата отклонённой картой (`4444 4444 4444 4442`, статус `DECLINED`).  
   Ожидаемый результат: уведомление об ошибке, в БД статус `DECLINED`.
2. Ввод короткого номера карты (`123`).  
   Ожидаемый результат: сообщение "Неверный формат".
3. Ввод месяца `13`.  
   Ожидаемый результат: сообщение об ошибке.
4. Ввод владельца кириллицей.  
   Ожидаемый результат: ошибка валидации.
5. Ввод CVC из двух цифр.  
   Ожидаемый результат: ошибка валидации.
6. Отправка пустого номера карты.  
   Ожидаемый результат: сообщение "Обязательное поле".

### Дополнительные проверки UI
- Переключение на вкладку "Купить в кредит".
- Отображение цены, миль и процентов на главной странице.
